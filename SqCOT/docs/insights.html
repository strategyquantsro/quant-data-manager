Four sections, one open panel

The initial chart overlay is a single toolbar. Markets, Summary, Events and Guide are mutually exclusive. Opaque backgrounds keep chart lines out of the text. The existing Update / Details panel remains in the indicator subwindow. Layout preferences survive reloads when RememberLayout is enabled.

Summary — understand the selected market

Shows hedger and large-speculator CPI, changes over one and four reports, the other normalization horizon, duration in an extreme, descriptive events, and data status. The status is computed from the SDK freshness policy. Missing values show “--”.

“Data ready” applies to the selected series; a missing comparison stays unavailable and must not be interpreted as agreement. The dependency observation timestamp is the latest observation among the up to 12 primary/paired reports read for the summary, not the provider's release time.

The COT identifier and price-chart symbol are both shown. Clicking a market does not change the price chart. Price confirmation is explicitly not evaluated.

Markets — scan, filter and compare

Keep the existing participant table, or enable Compare. Comparison mode replaces large speculators with the other horizon and, when width permits, replaces the small-trader column with the four-report change. The rightmost wide-layout column shows 12 miniature bars from oldest to newest and the count of consecutive reports in the current extreme. A trailing “+” means the full inspected history remained in that zone.

New events filters to rows whose latest report comparison has an event; it is not an unread filter. Stale rows can still have historical events. A star on a report date means the expected report is missing. If freshness cannot be verified, the footer reports it. Row tooltips retain details hidden on narrow charts.

Levels use 87/100, never 87%. Blue means low and orange means high. These are index levels, not ownership shares or probabilities. Changes use index points and actual report offsets; four reports need not be four weeks.

The heatmap reads the current published binary cache. Summary and EA historical reads use observed-revision records. Both use the same calculation engine, but strict historical results can differ from today's revised archive.

Events — inspect recent comparisons

Displays six report comparisons using revisions known now. This is deliberately labelled as a current-revision comparison, not an immutable log of signals that were available then. Use historical asOf timestamps and pinned snapshots in an EA to reconstruct what was available at a past decision time.

Guide — definitions without leaving MT5

Explains CPI vs CTI, thresholds, report shifts, rolling normalization and market mapping. On very narrow charts only the Summary toggle is shown; enlarge the chart to reveal all tabs. Full clipped text is available on hover.

Five event families

FamilyExact rule
Enter an extremeCurrent index ≥0.80 while previous <0.80; or current ≤0.20 while previous >0.20.
Exit an extremePrevious ≥0.80 and current <0.80; or previous ≤0.20 and current >0.20.
Large changeAt least +10 or −10 index points between adjacent reports; fixed descriptive threshold, not a statistical significance test.
Persistent changeThe third consecutive strictly rising/falling move; requires five reports to prove it was not already present. The fourth continuing move does not repeat this event.
Horizon agreement/conflictA new shared high, shared low or opposite-extreme relationship, compared with the preceding matched report. Both current and preceding dates must match across 52W/156W.

Several bits may coexist. A jump directly from high to low emits an exit and an entry. Merely remaining high/low is a state, not a new event. CTI supports descriptive participation changes in the heatmap; it has no inherent price direction. Summary and notifications use hedger CPI.

Neither CPI nor CTI reveals the number of contracts bought, shorts covered or open interest from these five normalized fields. A rolling normalization window can change the index without a corresponding new raw-position extreme.

Optional, explained notifications

Append-only visual inputs NotifyCOTEventsPopup and NotifyCOTEventsPush default to false. Set ShowMarketsPanel=true and enable the desired channel. MT5 push must already be configured. The first valid current summary after attachment/market switch becomes a baseline; historical comparisons are not replayed.

Later current-report changes include the selected identifier, report date, event names, hedger level and one-report change. Corrections of the same report are labelled revised comparisons; removing all previously detected events can produce a cancellation notice within the running session. A revised report's own revision number is also included.

Shared persisted notification keys suppress the same report/dependency-observation/event combination across charts and restarts. Failed push delivery is retried with existing throttling while the event remains applicable. Baselines are session-local: restart does not replay missed events. Notices cover the selected market only and require the selected series to pass CanTrade. The service's existing outage/publication alerts are separate.

The same calculations in an EA

Include SqCOTInsights.mqh. Keep one CSqCOTClient per horizon. Open live clients or immutable snapshots, poll them, then pass an explicit UTC decision time to:

SqCOTInsight result;
bool ok = COT_ReadInsight(shortClient, longClient, asOfUtc, result,
                          0,  // actual report shift, newest = 0
                          0); // field: 0 = hedger CPI
if(ok && (result.events & COT_EXIT_LOW) != 0) {
   // Descriptive setup only. Apply your own readiness / price / risk rules.
}

Inspect valid, delta1Valid, delta4Valid and paired; never treat an unavailable comparison as zero. Result fields include level, delta1/delta4, otherLevel, zone, extremeReports, durationCapped, horizon, events, reportDate, availableAtUtc, revision, generation, evaluatedAtUtc and dataStatus.

availableAtUtc is the maximum observation timestamp of inspected dependencies. revision refers to the primary selected report. valid means values can be analysed, not permission to trade. For new live entries require ReadLatest + CanTrade for every series your rule needs; require paired for horizon rules. Historical calls do not call live CanTrade; callers apply historical freshness and their execution policy.
